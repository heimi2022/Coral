# 899.703 MAC/cycle 波形分析

分析日期：2026-10-18。输入产物目录为
`/tmp/coral_matrix_gemm_512_after_899/`。
本次只增加分析脚本和记录，没有改 GEMM 的发射顺序或 RTL。

## 结论

当前主要损失在 N/M 分组边界。每个完整 N group 内的 8 条 MATMUL
已经连续输入激活，组内的 K tile 切换没有断流。

512x128x512 的运算包含 16 个 N group，每组复用一块 M tile，计算
四块 N tile，沿 K 执行两轮。每组有 32 个内部 32x32 block，连续输入
2048 拍激活。全部 512 个 block 共输入 32768 拍。

| 指标 | 本次观测 |
|---|---:|
| 从 execute_from 到 halted | 37295 周期 |
| 逻辑 MAC 数 | 33554432 |
| Logical MACs/cycle | 899.7032309961121 |
| 相对 32x32 阵列 1024 MAC/cycle 的端到端比值 | 87.86% |
| MatrixCore 接收 / 完成 MATMUL | 128 / 128 |
| MatrixCore 接收未完成峰值 | 3 |
| 激活读取 / 返回有效拍 | 32768 / 32768 |
| PE 权重读取有效拍 | 16384 |
| AXI 读 / 写 beat | 10560 / 16384 |
| MATMUL valid=1、ready=0 的拍数 | 0 |
| MatrixCore 访存 valid=1、ready=0 的拍数 | 15 |

激活输入有效拍不是全阵列所有 PE 的忙闲信号。停止输入后的数据仍会
经过阵列和累加器。这里用输入空档定位调度边界，不把每一拍输入空档
都解释成整片 PE 空闲，也不把 CPU 停顿拍数直接当成可节省周期。

## 时间分解

| 区间 | 次数 | 每次周期 | 合计周期 |
|---|---:|---:|---:|
| 首次激活前的启动、首批加载和 PE 装权 | 1 | 446 | 446 |
| 有效激活输入 | 16 | 2048 | 32768 |
| 同一 M tile 内切换 N group | 7 | 124 | 868 |
| 最后一次同一 M tile 内切换 N group | 1 | 128 | 128 |
| 切换 M tile | 7 | 394 | 2758 |
| 最后一次激活输入结束到 CPU halted | 1 | 327 | 327 |
| 总计 | | | 37295 |

除启动和收尾外，输入空档集中在 15 个分组边界。组内的 496 对相邻
block 起点间隔全部恰好为 64 拍，说明组内没有输入气泡。

各组恢复计算前都重新装入第一块 PE 权重，32 拍乘 16 组共 512 拍；
其它 PE 权重加载都与激活输入重叠。输入空档中控制器处于 Idle 的
总计 4000 拍。另外启动阶段有 10 个周期尚无 pe_ctrl 时钟上升沿，
5 个时钟采样点复位未释放。因此总时间也可核对为：

```text
32768 激活输入 + 512 单独装权 + 4000 控制器 Idle + 15 启动 = 37295
```

## M tile 边界的具体等待

以 M=0..63 切换到 M=64..127 为例，时间单位为 ns，仿真时钟周期
为 1.25 ns。这些时间用于波形定位，不表示综合后的工作频率。

| 时间 ns | 事件 |
|---|---|
| 5527.50 | 当前组最后一条 MATMUL C3 发射 |
| 5553.75 | 下一 M tile 的 A0 scale load 已被 DMA 接收 |
| 5667.50 | 下一 M tile 的 A0 payload 和 scale 均已完成 |
| 5728.75 | 下一组 B1 scale load 已被 DMA 接收 |
| 5843.75 | 下一组 B1 payload 和 scale 均已完成 |
| 5995.00 | 当前组最后一拍激活输入结束，进入输入空档 |
| 6041.25 | 当前 MATMUL C3 完成，同拍发射 STORE C3，PC=0x404 |
| 6043.75 | DMA 接收 STORE C3 |
| 6128.75 | CPU 到达 PC=0x568，ROB 剩余空间为 0 |
| 6387.50 | STORE C3 完成 |
| 6388.75 | PC=0x568 的 ROB 满等待结束 |
| 6442.50 | 下一组 MATMUL C0 才发射，PC=0x210 |
| 6487.50 | 下一组开始输入激活 |

下一组 A/B 在 5843.75 ns 已经就绪，比旧组激活输入结束还早。
因此这处空档不能归因于 A/B 没有预取。

程序仍先通过旧组 STORE C3，再走 N/M 循环收尾和下一 M tile 的
地址初始化。反汇编显示 0x518..0x5ec 存在大量地址重建、常量装入
以及栈读写。ROB 满时停在 0x568 的 `lui`；这一指令本身不依赖 C。
波形在 7 次 M tile 切换中，都观察到此处连续 208 拍 ROB 满。
该区间 DMA load 不忙，store 忙；STORE C3 完成后下一拍 ROB 恢复空间。

394 拍可以按事件间隔分为：

```text
37 拍：旧组停止输入后，等待 C3 MATMUL 完成并发射 STORE C3
321 拍：STORE C3 发射到下一组 MATMUL C0 发射
        其中包括 208 拍 ROB 满等待及标量准备
36 拍：下一组 MATMUL 接收到第一拍激活输入，含 32 拍 PE 装权
```

同一 M tile 内换 N group 时，中间这段通常只有 51 拍，故为
37+51+36=124 拍。它仍在等旧组 STORE C3 能够发射，但不需要等
该 STORE 完成：第一次 N 边界的下一条 MATMUL 在 3390.00 ns 已发射，
此时 STORE C3 仍在运行。这与 M 边界的 ROB 容量间接阻塞需要区分。

## 951 基线之前的软件优化方向

保留已经验证的组内 A0/A2、B1/B2/B3/B1 和 B3/B0/B1/B3 顺序。
优先减少 M 边界重复的地址初始化和栈读写，把完整形状的分组循环
组织得更紧凑，减少 STORE C3 后、下一条 MATMUL 前的标量指令。

另一项候选优化是让下一组首条 MATMUL C0 在旧组 STORE C3 阻塞
发射前进入命令队列。需要保持旧 C0 的 STORE 已被正确排序，且不得
为此提前覆盖当前 C2/C3 仍使用的 A/B；M/N/K 形状变化的尾块也不能
越过仍使用旧维度的 STORE。该方案已实现，大矩阵验证结果见后文
975.817 一节。

当前没有证据要求扩大 MatrixCore FIFO。ROB 满只在特定软件顺序下
形成跨 M 边界的损失，也不能直接把所有 ROB 满计数当成扩容收益。

## 下一组 C0 提前发射后的 975.817 结果

在 951.035 MAC/cycle 版本上，仅调整 GEMM 软件调度，不修改 RTL。
当当前组和下一组都是完整四块 N tile、K 是 64 的整数倍，且两组
属于同一 M tile 时，发射顺序改为：

```text
当前组最终 K tile：
MMACC C0
MMACC C1 -> STORE C0
MMACC C2 -> STORE C1
MMACC C3
LOAD 下一组 A0 / scale
LOAD 下一组 B1 / scale
MZERO C0 -> MMACC 下一组 C0 的第一个 K tile
STORE 当前组 C2
STORE 当前组 C3
下一组从 C1 继续第一个 K tile，跳过已经发射的 C0
```

旧 C0 的 STORE 已先于下一组 MZERO C0 发射，同寄存器的依赖交由
scoreboard 排序。提前发射不是跳过 C0 的写回，也不改变总 MMACC、
清零或 STORE 数量。即使 K 只有一块，下一组 C0 也只计算一次。

本节的 975.817 实测只覆盖同一 M tile 内的组间提前发射。随后软件
调度又扩展为：跨 M tile 时，只要当前和下一组的 `tile_m` 相同，也
允许提前下一组 C0；只有遇到较短的 M 尾块，才恢复先发射旧 C2/C3
STORE、再改变 M 维度的顺序。N 尾组和 K 尾块继续使用原有通用路径。

主机调度模型通过 347 种尺寸，检查输出、padding、指令数量以及
下一组 C0 是否实际出现在旧 C2/C3 STORE 之前。此模型同步执行
矩阵操作，不验证 RTL 时序、反压或硬件累加舍入。

2026-10-18，以下目录中的 512x128x512 波形和 metrics 已完成输出
校验，profile 的周期、激活拍数和 AXI beat 核对通过。此结果只代表
这个大矩阵用例，不替代尾块及反压用例的独立 RTL 验证。

| 指标 | 951.035 基线 | 下一组 C0 提前发射 |
|---|---:|---:|
| 总周期 | 35282 | 34386 |
| Logical MACs/cycle | 951.035 | 975.817 |
| 端到端 MAC/cycle / 1024 | 92.87% | 95.29% |
| 同 M 换 N group 输入空档 | 通常 117 | 0 |
| 换 M tile 输入空档 | 125 | 129 |
| 启动到首次激活 | 398 | 402 |
| 最后激活到 halted | 313 | 313 |
| 接收未完成 MATMUL 峰值 | 3 | 3 |

减少 896 周期，吞吐提升 2.61%。16 个 N group 现在连成 8 段，
每个 M tile 的两组连续输入 4096 拍激活。512 个内部 block 的
相邻起点间距为 504 次 64 拍和 7 次 193 拍，即仅跨 M 边界存在
129 拍空档。时间分解为：

```text
402 启动 + 32768 激活输入 + 7*129 跨 M 边界 + 313 收尾 = 34386
```

每次跨 M 边界的 129 拍可按事件分成：37 拍等待旧 C3 MMACC
完成并发射 STORE C3，56 拍到下一组 C0 MATMUL 接收，以及
36 拍到激活恢复（包含 32 拍 PE 装权）。第一次边界对应的时间为
5785.00、5831.25、5901.25、5946.25 ns。下一组 C0 已在旧
STORE C3 进行时发射，并未等待该 STORE 完成。

AXI 读 10560 beat、写 16384 beat，128 条 MATMUL、64 条清零和
64 条 STORE 数量不变。MatrixCore 的 MATMUL 和访存命令入口
均未观测到 valid&&!ready；CPU 仍有与计算重叠的 ROB 满等待，
不能将该计数直接当成端到端损失。

随后实施的等行数跨 M 扩展已完成本大矩阵用例的 RTL 仿真验证，
实测见下一节。主机模型同时覆盖同 M 和等行数跨 M 两种情况；
