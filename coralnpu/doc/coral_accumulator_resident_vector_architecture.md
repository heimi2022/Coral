# 面向矩阵 NPU 的累加器驻留向量执行架构

## 摘要

现代大模型计算通常由矩阵乘法和非线性变换交替组成。矩阵乘法适合由脉动阵列或其他专用矩阵执行单元完成，而 SiLU、GELU、sigmoid、归一化以及各种量化变换则需要逐元素算术、比较、选择和部分归约。两类计算的数据形状相同，却经常被放在不同的存储层和执行路径上。

本文提出一种**累加器驻留向量执行**的架构抽象：矩阵乘法的 C/Acc SRAM寄存器同时作为轻量向量操作的架构操作数。一条指令以整个 C reg 为对象，硬件在内部按 SRAM 行读取、计算和写回，直到完成该寄存器覆盖的全部行。行是实现中的物理处理粒度，C reg 是软件可见的指令粒度。该机制不要求引入完整 RVV，也不要求把矩阵结果先写回外部内存再交给独立向量单元。

本文的目标是定义问题、设计原则和可检验的架构边界，而不是冻结最终的指令编码或声称当前 RTL 已经实现全部功能。

## 1. 背景：矩阵计算之后仍然有大量工作

矩阵乘法通常承担模型中的主要乘加工作。例如，一个 Transformer 的线性
层可以抽象为：

```text
Y = X · W
Z = activation(Y + bias)
```

矩阵单元擅长计算第一步，但第二步包含的运算类型不同：

- 加偏置、缩放和量化需要逐元素算术；
- ReLU、clamp、maximum 和 minimum 需要逐元素比较与选择；
- SiLU、GELU、sigmoid 和 tanh 通常需要分段函数、查表或多项式近似；
- softmax 还需要按行或按序列进行最大值、指数近似、求和和归一化。

因此，矩阵乘法的峰值吞吐并不能直接转化为端到端算子吞吐。矩阵乘法
结束以后，部分和已经位于 NPU 内部的累加器存储中；如果非线性通路无法
直接使用这份数据，系统会在最接近计算完成的位置产生新的数据搬运边界。

## 2. 核心问题：计算密集路径与非线性路径之间存在断层

### 2.1 C/Acc SRAM 不是普通向量寄存器

矩阵单元的 C reg 通常由 SRAM 或寄存器阵列实现，按行或按 bank 访问。它
的容量和带宽围绕矩阵乘法设计，保存的是一个矩阵块的部分和，而不是若干
个标量寄存器的简单拼接。矩阵乘法完成后，结果最有价值的状态就是已经
驻留在这个局部累加器中。

如果架构只提供矩阵乘法和 load/store，非线性运算通常需要以下路径：

```text
C reg -> 外部存储或中间缓冲 -> 向量/标量执行单元 -> 再写回
```

这条路径会引入额外的数据搬运、缓冲空间、调度依赖和写回带宽。对于SiLU 或 GELU 这类每个元素只需要少量算术、但覆盖整个矩阵块的运算，搬运成本可能接近甚至超过计算本身。

### 2.2 现有方案各自解决了不同层面的问题

公开架构中已经存在若干相近思想：

- 一些 NPU 在矩阵单元后连接独立的 scale、bias、activation 或 post-processing
  数据通路；
- 一些加速器允许 Tensor ALU 从 accumulator scratchpad 读取数据并原地写回；
- 一些 GPU 和矩阵 ISA 把矩阵乘法结果放入普通寄存器片段，再使用 SIMD
  指令执行 epilogue；
- 完整向量 ISA 可以表达逐元素运算，但通常需要向量寄存器、向量长度和
  多条循环指令管理这块数据。

这些方案证明“矩阵结果需要继续做向量式处理”是普遍问题，但它们的存储
抽象、地址生成方式和软件可见的操作数粒度并不相同。尤其是，内部按行
访问的 SRAM 不必然意味着架构必须按行发出指令。

## 3. 严重性：为什么数据搬运边界值得单独解决

### 3.1 带宽代价

假设一个 C reg 包含 (R) 行，每行宽度为 (W) 字节。若逐元素操作前后
需要一次完整的写出和读回，则至少增加：

```text
额外流量约等于 2 × R × W
```

这部分流量不产生新的矩阵乘加结果，却会占用 DMA、片上缓冲和外部存储
带宽。对于连续的矩阵层和激活层，数据可能在短时间内被重复搬运多次。

### 3.2 延迟和流水线代价

外部向量路径需要等待写回完成、建立新任务、重新读取数据并处理尾块。
即使矩阵阵列本身保持高利用率，整个算子仍可能在矩阵和非线性阶段之间
出现气泡。软件还需要显式安排缓冲区、地址和循环边界。

### 3.3 指令与控制代价

如果没有合适的张量级操作数，软件只能逐行或逐片段发出指令。这样会把
本应由硬件完成的 SRAM 行遍历暴露给编译器和运行时，增加：

- 指令数量；
- 行地址和循环状态；
- C reg 复用的依赖管理；
- 矩阵单元与向量单元之间的同步点。

完整 RVV 可以解决表达能力问题，但会带来独立的向量寄存器、向量长度
配置、更多上下文状态和更复杂的实现。对于只服务于矩阵累加器后处理的
路径，这可能超出所需的硬件规模。

## 4. 提出的架构：累加器驻留的整寄存器向量操作

### 4.1 架构操作数与物理访问粒度分离

本方案定义两个层次：

```text
架构层：整个 C/Acc reg 是一次指令的操作数
实现层：SRAM 的一行或一个 bank 是内部每周期的处理单元
```

因此，一条指令可以抽象为：

```text
    C_reg <- UnaryOp(C_reg, parameters)
```

其中 `UnaryOp` 可以代表逐元素加常数、缩放、最大值/最小值、截断、
分段多项式或其他由轻量数据通路支持的操作。指令不需要为每一行提供
独立地址，也不要求软件展开完整的行循环。

这不是把 C reg 误认为一个单周期超宽组合寄存器。C reg 仍然由 SRAM 行
组成，操作可以持续多个周期；变化在于软件看到的是一次完整的寄存器级
事务，而不是一串暴露出来的行级事务。

### 4.2 原地读改写

执行单元从 C reg 读取一行，经由轻量向量数据通路计算后，把结果写回
同一行，随后继续处理下一行：

```text
for each row in C_reg:
    x = read(C_reg, row)
    y = elementwise_op(x, parameters)
    write(C_reg, row, y)
```

上述循环是实现模型，不是要求软件执行的程序。对软件而言，操作在最后
一行完成时统一报告 done；对硬件而言，行调度、读写时序和必要的局部
流水化均可隐藏在 MatrixCore 内部。

### 4.3 C reg 是矩阵计算和轻量向量计算的共同驻留点

矩阵 PE 产生的部分和直接留在 C reg 中。后续轻量向量操作复用同一存储，
从而形成：

```text
矩阵 MAC -> C/Acc SRAM -> 累加器驻留向量操作 -> 后续矩阵或写回
```

这里不需要新增一套完整 RVV 向量寄存器文件。向量数据通路只需覆盖矩阵
后处理所需的基本算术、比较、选择和格式转换能力，具体的函数复杂度可
通过分段多项式、常数参数或多次驻留操作表达。

## 5. 指令语义的抽象形式

最终编码可以根据工具链和 RTL 约束决定。架构层只需要保留以下语义：

```text
    op Cdst, operation, parameters
```

其中：

- `Cdst` 是一个完整的 C/Acc 寄存器编号；
- `operation` 指定轻量逐元素运算类别；
- `parameters` 可以是立即数、共享标量参数、格式信息或预定义函数选择；
- 目的寄存器与源寄存器可以是同一个 C reg，实现原地更新；
- 指令完成表示整个 C reg 的所有有效行都已经处理完毕。

这种语义不规定 C reg 的物理 SRAM 行数、每行位宽或内部流水级数。它只
规定了软件和硬件之间的边界：软件提交一个寄存器级操作，硬件负责把该
操作映射到完整的存储对象。

## 6. 依赖与并发模型

C reg 的读写依赖可以沿用矩阵寄存器的常规 scoreboard 机制。对于同一个
C reg，系统至少需要识别以下关系：

- 前一条矩阵累加尚未完成时，不能开始读取该 C reg；
- 驻留向量操作写回期间，不能被新的矩阵累加覆盖；
- 驻留向量操作完成后，C reg 才能作为下一条矩阵指令的累加目的；
- 若矩阵 PE 与轻量向量通路共享同一 C reg，应由寄存器级依赖阻止冲突访问。

这可以采用与 CPU 寄存器读后写、写后读和写后写约束相似的调度方式。关键
是按 C reg 建立依赖，而不是把每个 SRAM 行暴露成独立的架构寄存器。

对于不同 C reg，矩阵计算和向量操作仍可由 MatrixCore 的命令队列、
scoreboard 或后续更细粒度的资源调度机制进行重叠。这里的“整寄存器
指令”描述操作数范围，不等于要求整个 MatrixCore 在整个操作期间停止。

## 7. 对大模型非线性算子的支持边界

### 7.1 适合直接支持的操作

轻量数据通路可以自然支持：

- 加、减、乘以共享标量；
- 最大值、最小值、截断和符号处理；
- 量化、反量化和格式转换；
- 基于比较和选择的 ReLU、clamp 以及分段函数；
- 用低阶多项式或查表近似实现的 SiLU、GELU、sigmoid、tanh。

### 7.2 softmax 的边界

softmax 不是单纯的一次逐元素运算。典型实现至少包含：

```text
按行求最大值 -> 减最大值 -> 指数近似 -> 按行求和 -> 归一化
```

因此，整 C reg 指令可以直接承担其中的逐元素阶段，也可以配合专门的
行归约阶段完成完整流程。是否把归约和指数近似纳入同一条高层指令，属于
后续指令集设计问题，不能把“支持整寄存器逐元素操作”直接等同于“一条
指令完成 softmax”。

## 8. 与相关方案的边界

### 8.1 与 VTA 类 Tensor ALU 的区别

VTA 等加速器已经展示了 accumulator scratchpad 上的 Tensor ALU 和原地
读改写，这说明基础数据通路并非从零开始。区别在于操作数抽象：VTA 的
任务通常由微操作、地址和循环描述具体访问范围；本方案把完整 C reg 作为
架构操作数，并把 SRAM 行遍历隐藏在执行单元内部。

因此，本方案的主张不应写成“首次在累加器上做逐元素运算”，而应写成：

> 将矩阵累加器的整个 C reg 暴露为轻量向量操作的架构级操作数，并以单条
> 指令隐式覆盖该寄存器的全部有效 SRAM 行。

### 8.2 与独立后处理单元的区别

独立 post-processing 单元可以实现许多相同的数学函数，但通常需要在矩阵
单元和后处理单元之间定义数据流接口或缓冲区。本方案将处理位置固定在
累加器驻留点，重点减少矩阵结果离开局部存储的次数，并让 C reg 依赖成为
统一的调度边界。

### 8.3 与完整 RVV 的区别

完整 RVV 面向通用向量程序，提供向量寄存器、向量长度、掩码和广泛的
向量指令。本方案只提供面向矩阵累加器后处理的轻量数据通路：架构上以
整个 C reg 为对象，内部以 SRAM 行为工作单位，避免引入完整 RVV 的状态
和编程开销。

## 9. 预期收益

在相同的矩阵计算结果下，本方案预期带来以下收益：

1. **减少数据搬运**：非线性阶段直接消费 C reg，避免不必要的外部写回和
   再读取。
2. **缩短算子边界**：矩阵 MAC 与后处理在同一个局部驻留点衔接，减少缓冲
   和任务交接延迟。
3. **降低指令数量**：软件按 C reg 发起操作，不需要逐行展开地址和循环。
4. **保持硬件专用化**：只增加面向矩阵后处理的轻量数据通路，不承担完整
   通用向量 ISA 的实现成本。
5. **保留矩阵寄存器复用**：处理结果仍位于原有 C reg 中，可以继续参与后续
   矩阵操作或按原有路径写回。

## 10. 需要明确的限制

该抽象也会带来需要认真处理的工程和架构问题：

- 操作期间 C reg 处于忙状态，矩阵 PE 和向量通路必须遵守寄存器级依赖；
- 矩阵尾块需要有效行掩码或尺寸元数据，避免处理填充数据；
- 不同数据格式、饱和、舍入和异常语义必须在指令集中定义；
- 长时间的整寄存器操作可能占用 C reg 资源，需要命令队列进行公平调度；
- softmax 等归约密集算子不能只依赖逐元素通路；
- 现有 MatrixCore RTL 尚未因此文档自动获得新的指令或执行能力。

这些限制不否定该架构方向，反而定义了后续验证应测量的对象：C reg 驻留
时间、矩阵/向量切换代价、外部流量、尾块效率和非线性算子的端到端周期。

## 11. 可检验的架构贡献

为了避免把贡献描述得过宽，建议将研究问题限定为以下命题：

> 对以 SRAM 实现的矩阵累加器而言，把整个 C reg 作为轻量向量操作的架构
> 级操作数，并由硬件隐式遍历其内部行，相比“写回后由独立向量路径处理”
> 和“由微操作逐行描述访问范围”的方案，能否在保持较小硬件状态的同时，
> 降低数据流量、指令数和矩阵后处理的端到端延迟？

该命题可以通过三组对照实验检验：

| 方案 | 操作数表达 | 主要代价 |
| --- | --- | --- |
| 外部后处理 | C reg 写回缓冲，再由向量/标量单元读取 | 搬运带宽和缓冲延迟 |
| 微操作式累加器 ALU | uop、地址和循环描述访问范围 | 控制与地址暴露给软件/运行时 |
| 整 C reg 驻留操作 | 一条指令指定完整 C reg，内部隐式遍历 | C reg 占用和专用数据通路 |

建议至少测量：

- 每个 C reg 的额外指令数；
- 外部内存和片上缓冲的读写字节数；
- 矩阵乘法、后处理和写回之间的空泡周期；
- C reg 驻留时间与寄存器复用压力；
- SiLU、GELU、量化和 softmax 子阶段的端到端吞吐；
- 轻量数据通路的面积、功耗和控制状态量。

## 12. 结论

这个设计的核心不是把 SRAM 的一行重新命名为向量，也不是增加一个缩小版RVV。它建立了一个新的架构边界：**C reg 是矩阵累加器，也是后处理向量操作的整体操作数；行级访问属于实现细节，整寄存器操作属于指令语义。**

这一边界保留了矩阵 PE 的局部性，同时为矩阵结果提供了低成本的逐元素处理路径。相关工作已经覆盖累加器上的 ALU、独立后处理和通用向量执行，因此创新性应集中在上述组合的具体架构语义、依赖模型和可测量收益上，而不应笼统表述为“首次在 NPU 中支持非线性运算”。
