# SiLU 分段二阶近似规格

## 函数形式

目标激活函数为：'
$$
SiLU(x) = \frac{x}{1+e^{-x}}
$$
当前实现采用以下近似策略：

- 左侧尾部使用近似 `0` 的处理
- 中间非线性区间使用三段二阶多项式拟合
- 右侧尾部使用恒等映射近似

平滑后的分段规则为：

```text
x <= -16      -> 0
-16 < x < -1  -> p0(x)
-1  <= x < 2  -> p1(x)
2   <= x <= 8 -> p2(x)
x > 8         -> x
```

其中：

```text
p0(x) = a20 * x^2 + a10 * x + a00
p1(x) = a21 * x^2 + a11 * x + a01
p2(x) = a22 * x^2 + a12 * x + a02
```

为便于硬件实现，二阶多项式统一改写为 Horner 形式：

```text
p(x) = ((a2 * x) + a1) * x + a0
```

## 定点格式

当前 demo / 参考实现使用如下定点格式：

- 输入格式：`int16 Q6.10`
- 系数格式：`int16 Q6.10`
- 中间乘法结果格式：`int32`
- 输出格式：`int16 Q6.10`

缩放关系定义为：

```text
real_value = fixed_value / 2^10
```

关键阈值对应的定点表示为：

- `-16` -> `-16384`
- `-1`  -> `-1024`
- `2`   -> `2048`
- `8`   -> `8192`

## 计算公式

对落在多项式区间内的元素，按如下公式计算：

```text
t_q = ((a2_q * x_q) >> 10) + a1_q
y_q = ((t_q   * x_q) >> 10) + a0_q
```

其中右移 `10` 位的原因是：`x_q` 和 `a*_q` 都采用 `Q6.10` 格式，乘法后小数位数相加，因此需要右移 `10` 位，将结果重新拉回 `Q6.10` 格式。

尾部区间处理规则为：

```text
if x_q <= -16384: y_q = 0
if x_q >   8192:  y_q = x_q
```

## RVV 映射

当前 RVV demo 文件：

- [rvv_silu_demo.cc](/home/wjj/2-NPU/coralnpu/examples/rvv_silu_demo.cc)

每个向量批次的处理流程如下：

1. 将输入 `x_q` 读取为 `vint16m4_t`
2. 生成以下比较掩码：
   - `x <= -16`
   - `x < -1`
   - `x < 2`
   - `x > 8`
3. 通过 `vmerge` 按 lane 选择 `a2/a1/a0`
4. 使用两级 widening multiply 计算 Horner 多项式
5. 对尾部区间 lane 覆盖为 `0` 或 `x`

相关 RVV 指令包括：

- 比较类：`vmsle`、`vmslt`、`vmsgt`
- 系数选择：`vmerge`
- 多项式计算通路：
  - `vwmul`
  - `vnsra`
  - `vadd`

### 为什么当前 SiLU 通路被限制在 32 lane

当前 Coral RVV 配置中：

- `VLEN = 128`
- 本 kernel 的元素宽度 `SEW = 16`

对于普通 `16` 位向量指令，例如 compare、merge、add，其并行 lane 数由下式决定：

```text
lane_count = LMUL * VLEN / SEW
```

如果取 `LMUL = 4`，则：

```text
lane_count = 4 * 128 / 16 = 32
```

因此，以下指令每次最多可以覆盖 `32` 个元素：

- `vmsle`
- `vmslt`
- `vmsgt`
- `vmerge`
- `vadd`

但是，Horner 多项式通路中还包含 `vwmul`，它是 widening multiply：

```text
16-bit x 16-bit -> 32-bit
```

这件事的关键在于：widening 指令会保持逻辑 lane 数不变，但目标元素宽度翻倍。因此在 RVV 的寄存器组表示上，会变成：

```text
source: e16, m4
dest  : e32, m8
```

其原因如下：

- 源向量中有 `32` 个 `16` 位 lane
- widening 后，每个 lane 变成 `32` 位
- 如果仍然保留这 `32` 个 lane，目标寄存器总容量必须翻倍
- 因此目标 LMUL 也必须从 `m4` 变成 `m8`

从存储容量角度看也很直观：

```text
source payload = 32 lanes * 16 bits = 512 bits
dest payload   = 32 lanes * 32 bits = 1024 bits
```

由于当前配置下，一个架构向量寄存器长度只有 `128` bit：

- `m4` 对应 `4 * 128 = 512 bit`
- `m8` 对应 `8 * 128 = 1024 bit`

因此 `vwmul` 自然对应：

```text
vint16m4_t -> vint32m8_t
```

正是这个 widening 步骤限制了整条 SiLU kernel 的输入寄存器组大小。如果输入侧继续扩大到比 `m4` 更大的组，那么 widening 后的目标寄存器组就会超过 `m8`，不再适合作为当前实现的常规 RVV 寄存器分组。

因此：

- compare / merge / add 阶段本身还希望继续放大 `LMUL`
- 但多项式路径必须保证 `vwmul` 合法
- 所以输入向量类型最多只能停在 `e16,m4`
- 整条 SiLU 数据路的端到端并行度也就被限制在 `32` lane

简而言之：

```text
真正限制并行度的不是 compare / merge / add，
而是 Horner 多项式路径中的 widening multiply
```

这也是为什么当前软件 demo 以及吞吐分析都以 `32 elements / iteration` 为基准，而不是更大的 lane 数。

## 吞吐与指令成本

### 架构向量粒度

当前映射默认采用：

- `VLEN = 128`
- `SEW = 16`
- `LMUL = 4`

单次完整 RVV 迭代的最大元素数为：

```text
VLMAX = LMUL * VLEN / SEW = 4 * 128 / 16 = 32 elements
```

因此，一次完整向量迭代最多可处理 `32` 个 SiLU 元素。

### 静态 RVV 指令预算

对一个完整的 `32` 元素向量批次，当前实现大约需要以下 RVV 指令：

- `1` 条 `vsetvl`
- `1` 条 `vle16`
- `4` 条比较指令
- `3` 条 `vmv`
- `6` 条用于系数选择的 `vmerge`
- `2` 条 `vwmul`
- `2` 条 `vnsra`
- `2` 条 `vadd`
- `2` 条尾部覆盖用 `vmerge`
- `1` 条 `vse16`

总计：

```text
~24 RVV instructions / 32 elements
```

理想情况下，按 issue 数量估算的吞吐下界为：

```text
32 / 24 = 1.33 elements / cycle
```

但需要注意，这只是基于指令条数的乐观下界，默认假设：

- 每拍都能发出一条 RVV 指令
- load/store 没有额外 stall
- 后端流水没有额外结构性冲突

这里还未计入标量侧的循环控制开销。

### Cycle 级粗略模型

定义：

- `Lmul`：`vwmul` 的结果就绪延迟
- `Tmem`：超出名义 `vle16` / `vse16` 发射槽位之外的额外访存停顿
- `Tmisc`：额外 scoreboard、流水切换或实现相关延迟

对于当前 Horner 数据通路：

```text
vwmul -> vnsra -> vadd -> vwmul -> vnsra -> vadd
```

可采用如下的一阶 chunk 延迟模型：

```text
Tchunk ~= 24 + 2 * (Lmul - 1) + Tmem + Tmisc
```

其解释为：

- 静态指令预算贡献基础项 `24`
- 多项式链中有两级串行 widening multiply
- 每级乘法器相对单拍多出来的延迟，都会直接反映到依赖链上

在 `Tmem = 0`、`Tmisc = 0` 时，对应示例如下：

- `Lmul = 1` -> `Tchunk ~= 24 cycles`
- `Lmul = 2` -> `Tchunk ~= 26 cycles`
- `Lmul = 3` -> `Tchunk ~= 28 cycles`

对应的理想化吞吐为：

- `Lmul = 1` -> `32 / 24 = 1.33 elements / cycle`
- `Lmul = 2` -> `32 / 26 = 1.23 elements / cycle`
- `Lmul = 3` -> `32 / 28 = 1.14 elements / cycle`

对早期微架构评估而言，如果后端是较简单的 in-order RVV 实现，更实用的估计范围可以取为：

- `Lmul = 1` -> `24 to 30 cycles / 32 elements`
- `Lmul = 2` -> `26 to 34 cycles / 32 elements`
- `Lmul = 3` -> `28 to 38 cycles / 32 elements`

这些数字适合做架构比较和规模预估，不应视为 RTL 波形实测或性能计数器测得的精确 cycle 数。

## 误差总结

在完整 `Q6.10` 可表示输入范围上，相对于浮点 SiLU 的误差统计为：

- `MAE = 0.00678215`
- `RMSE = 0.01523320`
- `Max abs error = 0.07812269`

平滑 `-16` 边界之后，最坏点约为：

- `x ~= -15.7324`
- approximation `~= -0.078125`
- true value `~= -0.000002`

说明：

- 将 `x = -16` 纳入左尾部分支后，消除了该边界处明显的跳变
- 当前剩余的最坏误差仍然集中在负侧尾部过渡区
- 在真值接近 `0` 的位置，相对误差并不稳定，因此更适合关注 `MAE` 和 `RMSE`
